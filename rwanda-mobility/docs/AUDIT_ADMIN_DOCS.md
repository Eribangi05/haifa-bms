# Audit: operations console, documentation and delivery

Scope: `admin-web/` (the staff console), `docs/` (except the generated `API.md` and `PERMISSION_MATRIX.md`, and the other audits), `deploy/`, `render.yaml`, the GitHub Actions workflow, `README.md` and the browser scripts in `backend/scripts/*-e2e.ts`. The backend source, backend tests and the mobile app were being audited by other people at the same time and were **not edited**: where this audit found a problem there, it is listed as *Open (backend)* for them.

Method: every tab was opened in Chromium (Playwright, real TOTP sign-in) as each of the nine staff roles at 1280 px and 768 px; behaviour checks drove tables, forms, dialogs, exports and the phone menu; the dashboard's numbers were re-derived with SQL; the documentation was compared with `backend/src/config.ts`, the migrations and the running schema, and a script now checks links and variables. Screenshots are in `/tmp/shots/admin-audit-*.png` (not committed).

Severity: **High** = wrong data, blocked work or a security/availability risk; **Medium** = real usability or correctness problem with a workaround; **Low** = polish or accuracy.

## Verified OK (observed, not assumed)

* Every one of the 18 tabs, for each of the 9 staff roles, at 1280 px and 768 px: no failed API call, no script error, no sideways page scroll, a page title, and the correct page (not a fallback) (`admin-audit-e2e.ts`).
* The tabs shown for each role equal the permissions in `backend/src/rbac.ts`; the console's copy of the table equals `rbac.ts`.
* Dashboard: requests, completed, cancelled, no-driver, gross booking value and commission for a fixed 30-day window equal direct SQL; the "Requests" card equals the API; 7-day sparklines render.
* Tables: sort, filter, empty message, status filter on the server, CSV (BOM, header, one line per row, no formula characters), finance CSV export download.
* Booking dialog opens from a row and closes with Esc; the dispatcher sees dispatch actions but no refund or dispute; the support agent can dispute but not cancel or refund; the finance officer has no Bookings or Staff tab and can reconcile; assigning requires a driver and a reason.
* Forms: staff invite rejects a bad e-mail and stays open; reconciliation rejects invalid JSON and names an invalid row; passenger search needs two characters; request-code form validates, creates a code, downloads a PNG QR (PNG signature checked) and deactivates it.
* Staff: invitation flow end to end (admin never sees the secret, invitee enrols and signs in); disable blocks sign-in and enable restores it.
* Session: a corrupted access and refresh token ends on the sign-in page with an explanation.
* Live map: tiles load; with tile requests aborted the notice appears and the tables remain; the page makes no third-party script request.
* Phone width (390 px): menu hidden until opened, closes after choosing a page, no sideways scroll. Dark theme switches and is remembered.
* Pricing, Settings, Promotions and Services screens still work with the new shell (`admin-pricing-e2e.ts` passes: self-approval, validation, preview equals API preview, proposal, approval, itemised peak line in a real estimate).
* Docs: 0 broken relative links or heading anchors across 24 markdown files; every file in `docs/` and `store/` is linked from the README; package id `rw.abasare.app` is the same in `app.config.js`, `ANDROID_BUILD.md`, `FEATURE_STATUS.md` and `store/LISTING.md`; store titles and short descriptions are within Play limits (30 and 80 characters); the old project name survives only in the README title, folder names and the backend default noted in B-03.
* Delivery: `render.yaml` health path `/health` exists and returns 200; the compose, workflow and blueprint YAML parse; every variable set in the blueprint, compose and both `.env.example` files is read by the code; the server runs migrations on start.

## Not verified

* **`docker build` and `docker compose up`** (no Docker daemon in the audit environment) and the **GitHub Actions workflow** (never executed). The install and start-up path was reproduced by hand; image layers, the `HEALTHCHECK`, volume permissions and Caddy were reasoned, not run.
* **Render dashboard behaviour** (rollback button, auto-deploy after rollback) and the **MTN, SMS aggregator and Expo secret-rotation steps**: written from configuration and public documentation; the runbook says so.
* The **backup and restore commands** were not run against Postgres on a compose stack; the SQL in the runbook was run against the dev schema.
* Browsers other than Chromium, a real phone, touch input, screen readers, and a measured colour-contrast check (tokens were chosen for contrast; not computed). Printing the QR poster and the *Use my current location* button (they open a print window and a permission prompt).
* **Money-moving and destructive buttons were not clicked** in a browser: approve/reject refund, approve/pay/reject payout, waive fee, execute privacy deletion, driver approve/suspend, business activation. Their endpoints are covered by the backend tests; the console's gating and dialogs for them were reviewed by reading and, for refund/assign dialogs, validated in the browser up to the confirm button.
* The Live map with **real moving drivers** (none was online in the audit data) and the dashboard on a large production database (the trend lines issue 7 aggregate queries).
* `docs/API.md` and `docs/PERMISSION_MATRIX.md` were not regenerated (generated files owned by another process); the backend suite was not re-run here.

## Remaining recommendations

1. Give the list endpoints an offset or cursor (B-01) and add one `GET /admin/dashboard/series` endpoint, then replace the seven trend calls.
2. Add console pages for client errors and cash remittance/adjustments; add a visible "your session ends in 2 minutes" prompt if the access token lifetime is short.
3. Write the `DATA_ENC_KEY` re-encryption script and rehearse it; version the ciphertext (`v1:`) first.
4. Run `docker compose up` and `docker build` once on a real host and execute the restore drill in the runbook; record the time it took.
5. Add a CI step that runs `npm run docs` and fails on a diff in `docs/API.md` and `docs/PERMISSION_MATRIX.md` (needs a decision from whoever owns the generator).
6. Replace the free OpenStreetMap tile server for the console map and the app before production-scale use (usage policy), and consider a Content-Security-Policy *header* from the server for `/admin/` instead of the meta tag.
7. Move uploaded documents to an S3-compatible bucket (the volume is single-host) and run more than one API instance only after the jobs move out of process.
8. Add a metrics endpoint (request rate, error rate, pool usage, job lag) so the alerts in the runbook do not depend on SQL polling.
9. Persist table filters across reloads of a page (they reset after an action) and add service and zone filters to the Overview (the API already accepts them).
